A new order service stores its orders in DynamoDB. It reads them in two ways:

1. fetch one order by its id, and
2. list one customer's orders, newest first.

Traffic is spiky and hard to predict, so nobody wants to manage capacity.

Create the table `${TABLE}`:

- partition key `orderId` (string), and no sort key
- **on-demand** capacity
- a global secondary index `by-customer` with partition key `customerId` (string) and sort key `createdAt` (string, an ISO 8601 timestamp), projecting **all** attributes
