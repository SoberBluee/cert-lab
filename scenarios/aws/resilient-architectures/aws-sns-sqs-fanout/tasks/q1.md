Checkout publishes one event per order, and two independent services consume it. A failure in one service must not lose the event for the other, and a message that keeps failing must be set aside instead of retried forever.

Create three SQS standard queues:

- `orders-dlq`, which keeps messages for **14 days**
- `billing` and `shipping`, each with a visibility timeout of **60 seconds** and a redrive policy that moves a message to `orders-dlq` after **${MAX_RECEIVES}** receives
