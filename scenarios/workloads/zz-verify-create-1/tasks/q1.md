Use context: `kubectl config use-context kubernetes-admin@kubernetes`

1. Create a Deployment `${Q1_NAME}` in namespace `${Q1_NS}` that runs `${Q1_REPLICAS}` replicas of image `${Q1_IMAGE}`, with the Pod label `app=${Q1_NAME}`. All replicas must be ready.

   - Expose it with a Service `${Q1_NAME}` of type `${Q1_EXPOSE_TYPE}` on port `${Q1_EXPOSE_PORT}`, forwarding to container port `80`.
   - The container requests `${Q1_RES_CPU}` CPU and `64Mi` memory, and is limited to `1` CPU and `${Q1_RES_MEMORY}` memory.
   - Add a readiness probe doing an HTTP GET of `/` on port `80`, and a liveness probe opening a TCP connection to port `80`, both every `${Q1_PROBES_PERIOD}` seconds.
   - Create a ConfigMap `${Q1_ENV_OBJ}` with the key `${Q1_ENV_KEY}` set to `${Q1_ENV_VALUE}`, and give the container `${Q1_ENV_KEY}` as an environment variable taken from it.
   - Its Pods must only run on nodes labelled `disk=${Q1_PLACE_DISK}`.
   - Create a ConfigMap `${Q1_NAME}-html` whose key `index.html` is `${Q1_HTML_TEXT}`, and mount it at `/usr/share/nginx/html`.
   - Create a ServiceAccount `${Q1_SA_SA}` and run the Pods as it, without mounting its API token.
   - Create a PriorityClass `${Q1_PRIO_CLASS}` with value `${Q1_PRIO_VALUE}` (not the global default) and give it to the Pods.
   - Keep at most `${Q1_REV_HISTORY}` old ReplicaSets, and count a Pod as available only after it has been ready for `${Q1_REV_MINREADY}` seconds.

2. Then update `${Q1_NAME}` to image `${Q1_UPDATE_IMAGE}` with a rolling update. Do not delete or recreate it.

3. Then scale `${Q1_NAME}` to `${Q1_SCALE_REPLICAS}` replicas.

4. Then change the rollout strategy of `${Q1_NAME}` to `RollingUpdate` with `maxSurge: ${Q1_STRATEGY_SURGE}` and `maxUnavailable: ${Q1_STRATEGY_UNAVAILABLE}`.

5. Then roll `${Q1_NAME}` back to its previous revision.

6. Then record `${Q1_CAUSE_CAUSE}` as the change cause of the current revision of `${Q1_NAME}`, so it shows in `kubectl rollout history`.

7. Then add the environment variable `${Q1_SETENV_KEY}=${Q1_SETENV_VALUE}` to the container of `${Q1_NAME}`, without recreating the Deployment.

8. Then restart every Pod of `${Q1_NAME}` with a rolling restart, without changing its spec by hand.

9. Then autoscale `${Q1_NAME}` between `${Q1_HPA_MIN}` and `${Q1_HPA_MAX}` replicas, targeting `${Q1_HPA_CPU}%` average CPU utilization.
