Use context: `kubectl config use-context kubernetes-admin@kubernetes`

1. Create a Pod `${Q2_NAME}` in namespace `${Q2_NS}` with one container `main` running image `${Q2_IMAGE}`. It must keep running.

   - Mount an `emptyDir` volume named `data` at `/data`. The container runs a shell command that appends the output of `date` to `/data/out.log` every 5 seconds, forever, and also prints it to standard output.
   - Add a second container `tailer` (image `busybox:1.36`) that mounts the same volume and streams `/data/out.log` to its standard output with `tail -F`.
   - Create a ConfigMap `${Q2_ENV_OBJ}` with the key `${Q2_ENV_KEY}` set to `${Q2_ENV_VALUE}`, and give the container `${Q2_ENV_KEY}` as an environment variable taken from it.
   - The container runs as user `${Q2_SEC_USER}`, with a read-only root filesystem and no privilege escalation.
   - The container requests `${Q2_RES_CPU}` CPU and `64Mi` memory, and is limited to `1` CPU and `${Q2_RES_MEMORY}` memory.
   - PersistentVolume `${Q2_PVC_CLAIM}-pv` (StorageClass `manual`) exists. Create a PersistentVolumeClaim `${Q2_PVC_CLAIM}` requesting `${Q2_PVC_SIZE}` (`ReadWriteOnce`) that binds to it, and mount it at `${Q2_PVC_MOUNT}`.
   - Before `main` starts, an init container `prepare` (image `busybox:1.36`) writes `${Q2_INIT_TEXT}` to `/init/ready` on an `emptyDir` volume that `main` also mounts at `/init`.
   - Create a ConfigMap `${Q2_FILES_OBJ}` with the key `${Q2_FILES_FILE}` set to `${Q2_FILES_VALUE}`, and mount it read-only at `/etc/app`, so the file `/etc/app/${Q2_FILES_FILE}` holds the value.
   - The container drops all Linux capabilities and adds back only `${Q2_CAPS_CAP}`.
   - Add a liveness probe that runs `ls /` in the container every `${Q2_PROBE_PERIOD}` seconds.
   - It must run on `${Q2_PLACE_NODE}`, set directly with `nodeName` (no nodeSelector or affinity).

2. Then add the label `${Q2_LABEL_KEY}=${Q2_LABEL_VALUE}` to the running Pod `${Q2_NAME}`, without recreating it.

3. Then add the annotation `${Q2_NOTE_KEY}=${Q2_NOTE_VALUE}` to the running Pod `${Q2_NAME}`, without recreating it.

4. Then change the image of container `main` in the running Pod `${Q2_NAME}` to `${Q2_UPDATE_IMAGE}`, without deleting the Pod.

5. Then raise the CPU request of `main` in the running Pod `${Q2_NAME}` to `${Q2_RESIZE_CPU}` with an in-place resize, without recreating the Pod.

6. Then, on the `controlplane` node, save the logs of container `main` of `${Q2_NAME}` to `/opt/${Q2_NAME}.log`.

7. Then copy `/data/out.log` from container `main` of `${Q2_NAME}` to `/opt/${Q2_NAME}-out.log` on the `controlplane` node.
