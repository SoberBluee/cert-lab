Use context: `kubectl config use-context kubernetes-admin@kubernetes`

Create a Deployment `${Q1_DEPLOY}` in namespace `${Q1_NS}` with `4` replicas and Pod label `app=${Q1_DEPLOY}`:

- An init container `seed` (image `busybox:1.36`) writes `<h1>${Q1_DEPLOY}</h1>` to `index.html` in a shared `emptyDir` volume.
- Container `web` (image `nginx:1.27-alpine`) serves that volume from `/usr/share/nginx/html`, and writes its logs as files to `/var/log/nginx` on a second `emptyDir` volume.
- `log-tail` (image `busybox:1.36`) follows `/var/log/nginx/access.log`, so that `kubectl logs ... -c log-tail` shows every request. Run it as a **native sidecar**: it must not be a regular container, and `web` must be the only one of those.
- Spread the Pods over the nodes with a topology spread constraint on `kubernetes.io/hostname`: `maxSkew: 1`, and never schedule a Pod that would break it.

All `4` replicas must be running, `2` on each worker. Do not change any node or its taints.
