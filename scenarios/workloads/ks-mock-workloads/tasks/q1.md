Use context: `kubectl config use-context kubernetes-admin@kubernetes`

Create a Deployment `${Q1_DEPLOY}` in namespace `${Q1_NS}` with `3` replicas and Pod label `app=${Q1_DEPLOY}`:

- An init container `seed` (image `busybox:1.36`) writes `<h1>${Q1_DEPLOY}</h1>` to `index.html` in a shared `emptyDir` volume.
- Container `web` (image `nginx:1.27-alpine`) serves that volume from `/usr/share/nginx/html`. It requests `50m` CPU and `64Mi` memory and is limited to `128Mi` memory.
- nginx must write its logs as files to `/var/log/nginx`, on a second `emptyDir` volume. A sidecar container `log-tail` (image `busybox:1.36`) follows `/var/log/nginx/access.log` so that `kubectl logs ... -c log-tail` shows every request.
- No two Pods of `${Q1_DEPLOY}` may ever run on the same node. Use a **required** rule, not a preferred one.

Leave the Deployment at 3 replicas, even though not all of them can run. Then write the scheduler's reason why the remaining Pod is not running to `/opt/course/q1/pending-reason.txt` on `controlplane`. Copying the event message is enough.
