Use context: `kubectl config use-context kubernetes-admin@kubernetes`

1. Create a Deployment `${Q2_NAME}` in namespace `${Q2_NS}` that runs `${Q2_REPLICAS}` replicas of image `${Q2_IMAGE}`, with the Pod label `app=${Q2_NAME}`. All replicas must be ready.

   - Expose it with a Service `${Q2_NAME}` of type `${Q2_EXPOSE_TYPE}` on port `${Q2_EXPOSE_PORT}`, forwarding to container port `80`.
   - Add an init container `content` (image `busybox:1.36`) that writes `${Q2_INIT_TEXT}` to `index.html` in an `emptyDir` volume, mounted at `/usr/share/nginx/html` in the main container.
   - Keep at most `${Q2_REV_HISTORY}` old ReplicaSets, and count a Pod as available only after it has been ready for `${Q2_REV_MINREADY}` seconds.
   - Spread the replicas over the nodes with a topology spread constraint: `maxSkew: 1` on `kubernetes.io/hostname`, `DoNotSchedule`, ignoring nodes whose taints the Pods do not tolerate.
   - Create a Secret `${Q2_ENV_OBJ}` with the key `${Q2_ENV_KEY}` set to `${Q2_ENV_VALUE}`, and give the container `${Q2_ENV_KEY}` as an environment variable taken from it.
   - Add a readiness probe doing an HTTP GET of `/` on port `80`, and a liveness probe opening a TCP connection to port `80`, both every `${Q2_PROBES_PERIOD}` seconds.
   - Create a ServiceAccount `${Q2_SA_SA}` and run the Pods as it, without mounting its API token.
   - Publish it with an Ingress `${Q2_NAME}` of class `traefik`: host `${Q2_INGRESS_SUB}.${Q2_NS}.lab`, path `/` (`Prefix`), to Service `${Q2_NAME}` on port `${Q2_EXPOSE_PORT}`. Traefik serves Ingress traffic on NodePort `30080` of every node.
   - Create a PriorityClass `${Q2_PRIO_CLASS}` with value `${Q2_PRIO_VALUE}` (not the global default) and give it to the Pods.
   - Publish it with an HTTPRoute `${Q2_NAME}` attached to Gateway `traefik-gateway` in namespace `traefik`: host `${Q2_ROUTE_SUB}.${Q2_NS}.lab`, to Service `${Q2_NAME}` on port `${Q2_EXPOSE_PORT}`. The Gateway serves on NodePort `30080` of every node.
   - The container requests `${Q2_RES_CPU}` CPU and `64Mi` memory, and is limited to `1` CPU and `${Q2_RES_MEMORY}` memory.

2. Then add the environment variable `${Q2_SETENV_KEY}=${Q2_SETENV_VALUE}` to the container of `${Q2_NAME}`, without recreating the Deployment.

3. Then scale `${Q2_NAME}` to `${Q2_SCALE_REPLICAS}` replicas.

4. Then restart every Pod of `${Q2_NAME}` with a rolling restart, without changing its spec by hand.

5. Then change the rollout strategy of `${Q2_NAME}` to `RollingUpdate` with `maxSurge: ${Q2_STRATEGY_SURGE}` and `maxUnavailable: ${Q2_STRATEGY_UNAVAILABLE}`.

6. Then update `${Q2_NAME}` to image `${Q2_UPDATE_IMAGE}` with a rolling update. Do not delete or recreate it.
