Use context: `kubectl config use-context kubernetes-admin@kubernetes`

`/opt/course/kustomize/${Q1_APP}-envs` on `controlplane` holds a Kustomize base and two overlays, `staging` and `prod`, both already applied, to namespaces `${Q1_APP}-staging` and `${Q1_APP}-production`. Until now `${Q1_APP}` was scaled by hand from ConfigMap `${Q1_APP}-scaling`. Replace that with a HorizontalPodAutoscaler:

1. Remove ConfigMap `${Q1_APP}-scaling` from the Kustomize config, and from both namespaces.
2. Add a HorizontalPodAutoscaler `${Q1_APP}` to the base. It keeps Deployment `${Q1_APP}` between `1` and `4` replicas, targeting `50%` average CPU utilization.
3. In prod the autoscaler may go up to `6` replicas. Set this with a patch in the prod overlay, not in the base.
4. Apply both overlays with `kubectl apply -k`.

`kubectl kustomize` must still build the base and both overlays.
