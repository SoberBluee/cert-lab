Use context: `kubectl config use-context kubernetes-admin@kubernetes`

Node `${Q5_NODE}` goes into maintenance, but the Pod `scratch` in namespace `${Q5_NS}` on it holds data that must not be lost, so you may **not** drain the node.

1. Mark `${Q5_NODE}` unschedulable, and label it `maintenance=true`.
2. Move all Pods of Deployment `${Q5_APP}` (namespace `${Q5_NS}`) off `${Q5_NODE}` by changing the Deployment: it must **require** nodes that are not labelled `maintenance=true`. All `4` replicas must end up ready on other nodes.
3. `scratch` keeps running on `${Q5_NODE}`, and PodDisruptionBudget `${Q5_APP}-pdb` stays unchanged.
