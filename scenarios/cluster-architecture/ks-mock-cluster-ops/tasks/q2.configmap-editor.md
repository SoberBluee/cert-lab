Use context: `kubectl config use-context kubernetes-admin@kubernetes`

Create a ServiceAccount `${Q2_SA}` in namespace `${Q2_NS}` for a configuration sync tool.

- Create a ClusterRole `${Q2_SA}-config` that allows `get`, `list`, `watch`, `create`, `update`, `patch` and `delete` on ConfigMaps. Other teams will reuse it later.
- Grant it to `${Q2_SA}` so that it applies **in namespace `${Q2_NS}` only**. Do not create a ClusterRoleBinding for this ServiceAccount.

`${Q2_SA}` must not be able to read Secrets, and must not be able to touch ConfigMaps in any other namespace.

Finally, create a Deployment `${Q2_SA}-probe` in `${Q2_NS}` with `1` replica of image `nginx:1.27-alpine` that runs as ServiceAccount `${Q2_SA}`.
