Use context: `kubectl config use-context kubernetes-admin@kubernetes`

Create a ServiceAccount `${Q2_SA}` in namespace `${Q2_NS}` for the release pipeline. Grant it exactly these permissions:

- In namespace `${Q2_NS}` only: `get`, `list`, `watch`, `create`, `update` and `patch` on Deployments, and `get` and `list` on Pods.
- Cluster-wide: `get` and `list` on Nodes.

It must **not** be able to delete Deployments, read Secrets, or create Deployments in any other namespace. Name the Role `${Q2_SA}-role` and the ClusterRole `${Q2_SA}-nodes`; the binding names are up to you.

Finally, create a Deployment `${Q2_SA}-probe` in `${Q2_NS}` with `1` replica of image `nginx:1.27-alpine` that runs as ServiceAccount `${Q2_SA}`.
