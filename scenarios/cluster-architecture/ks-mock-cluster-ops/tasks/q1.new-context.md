Use context: `kubectl config use-context kubernetes-admin@kubernetes`

The kubeconfig of user `ubuntu` on `controlplane` (`~/.kube/config`) already holds the credentials of user `${Q1_USER}`. That user now joins a team that works in namespace `team-${Q1_USER}`.

1. Create namespace `team-${Q1_USER}`.
2. In that kubeconfig, add a context `${Q1_USER}-team` that uses user `${Q1_USER}`, cluster `kubernetes` and default namespace `team-${Q1_USER}`. Do **not** switch to it: the current context must stay `kubernetes-admin@kubernetes`.
3. Allow `${Q1_USER}` to manage common workload resources (Deployments, Pods, Services and so on) in `team-${Q1_USER}` only. Use the built-in ClusterRole `edit`.

As user `ubuntu`, `kubectl --context ${Q1_USER}-team get pods` must work afterwards.
